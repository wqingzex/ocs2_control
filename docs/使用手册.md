# 使用手册

从首次部署到日常操作：初始化、启动模块、网页控制台、遥操作（XR 头显、手柄）、相机、录制回放、出问题时怎么收集日志，以及上真机的逐步验证。原理见 [`robot_control_suite控制原理.md`](robot_control_suite控制原理.md)，故障码见 [`故障码.md`](故障码.md)。

## 1. 系统组成

```
XR 头显（XRoboToolkit App）
   │ 局域网
   ▼
XRoboToolkit PC Service（本机）
   │ 本机 gRPC（127.0.0.1:60061）
   ▼
xr_teleop xr_bridge_node（节点名 /xr_target_node）
   │ /teleop/head_pose /teleop/left_ee_pose /teleop/right_ee_pose /teleop/controller_state
   │ /teleop/trigger_values /teleop/grip_values /teleop/connection_status
   ▼
target_generator / XrInputHandler ──/left_target /right_target──▶ 控制器（MPC）

相机（头部 + 左右腕）──▶ /camera_{head,left_wrist,right_wrist}/color/image_raw/compressed
```

每个部分是一个**独立进程、独立日志**的模块，由 `./scripts/start.sh` 或网页控制台启停：

| 模块 | 内容 | 依赖 |
|---|---|---|
| `pc_service` | XRoboToolkit PC Service（只停止自己启动的） | — |
| `control` | 运控 launch（控制器 + target_generator，`launch_mode:=control_only`，不带 RViz） | — |
| `joystick` | 手柄遥操作；**按需**，不会被"全部启动"带起，也不会自动启动运控 | `control` |
| `rviz` | RViz（`launch_mode:=rviz_only`，带 FSM / 手 / 关节面板）；**按需**，窗口出现在机器人屏幕上 | `control` |
| `xr` | xr_bridge_node | `pc_service` |
| `camera_head` / `camera_left_wrist` / `camera_right_wrist` | 每台相机一个驱动进程，某台故障不影响其他模块 | — |

## 2. 首次部署：`./scripts/setup.sh`

```bash
git clone --recurse-submodules --shallow-submodules git@github.com:wqingzex/robot_control_suite.git && cd robot_control_suite
./scripts/setup.sh                 # 完整初始化：依赖、本机配置、SDK、编译、相机、手、XR 配对、检查
./scripts/setup.sh config          # 只生成或补全本机配置（--entry whole_body|split_body|dual_arm）
./scripts/setup.sh cam             # 只重新配置相机（失败重试无需重做依赖和编译）
./scripts/setup.sh cam --from      # 从相机步骤继续：相机 → 手 → XR 配对 → 最终检查
./scripts/setup.sh ee             # 只配置末端（左右手）
./scripts/setup.sh xr              # 只做头显配对
./scripts/setup.sh marvin          # 选择天机臂 SDK 版本：338 或 343
./scripts/setup.sh build           # 只编译
./scripts/setup.sh dyn             # 负载辨识：逐臂询问，确认后写入 robot.end_effector.dyn_param.left / right
./scripts/setup.sh dyn --reset     # 恢复默认负载（旧值记在 logs/dyn_identify/）
./scripts/setup.sh check           # 只做最终配置检查
./scripts/setup.sh --force         # 完整流程里也重新配置已配置的步骤
```

### 新机器：一步一步

前提：已装 ROS 2 Jazzy 和 `rosdep`；臂、相机、手、头显接好并上电（`cam`、`ee`、`xr` 步骤要用到）。

**机器是默认配置（fa_w2 全身真机）**：克隆后直接运行 `./scripts/setup.sh`，一条命令走完全部步骤。第 2 步 `config` 询问控制入口（回车用 `whole_body`），然后从模板生成 `config/robot.local.yaml`；之后依次是选天机臂 SDK 版本、编译、相机弹窗确认、手弹窗确认、负载辨识（逐臂询问，默认不辨识）、头显配对、最终检查。

**机器不是默认配置（双臂、分体、仿真，或手的型号不同）**：`setup.sh` 不会在中途停下来等你改配置，所以先生成配置、改好，再跑完整流程。`config` 不需要先装依赖：

```bash
./scripts/setup.sh config --entry dual_arm   # 生成 config/robot.local.yaml
# 编辑它，改带 [必改] 标记的项：robot.entry、robot.hardware、robot.base.type、
#   robot.end_effector.type、robot.end_effector.interface.bus
./scripts/setup.sh                           # 配置已存在，从这里接着做
./scripts/start.sh check                     # 校验配置和设备
```

某一步失败会立即停止，不会继续后面的步骤，也不会报"初始化完成"。修好后只重跑那一步（`./scripts/setup.sh cam`），或从那一步往后重跑（`./scripts/setup.sh build --from`）。

**更新代码之后**：模板新增了键时，已配置好的机器运行一次 `./scripts/setup.sh config`，几秒钟把缺的键补上，不用重跑依赖和编译。

### 步骤和状态

完整流程先列出每步状态，**只执行"需配置"的步骤**；单步命令永远重新配置。单步命令后加 `--from` 会按固定顺序执行该步及之后的全部步骤。容器里同样运行，只跳过物理机的 udev 和 CAN 操作。

| 步骤 | 做什么 |
|---|---|
| `deps` | 子模块 + `rosdep install`（网络超时自动重试） |
| `config` | 没有 `config/robot.local.yaml` 就按 `--entry`（不传则询问，`--yes` 用 `whole_body`）从模板生成；已有就补上缺的键，保留你的值和注释，原文件备份为 `.bak`；不在模板里的键只列出，不删除。文件完整时完整流程跳过它 |
| `host` | Orbbec udev 规则、腰部 CAN 免密 sudo（只放行 `ip link set can0 down/up ...`）、PC Service deb；需要 sudo |
| `marvin` | 选择天机臂 SDK 版本：338（38 版固件）或 343（43 版及以上），**要和臂的控制器固件一致，选错时驱动连上臂后会立即急停**。写入 `robot.arm.interface.firmware`，配置里已有就跳过；`--yes` 时沿用已编译的版本，没编译过用 343 |
| `build` | 增量编译整个工作区（按 `robot.arm.interface.firmware` 选天机臂 SDK），跳过 ocs2_ros2 里用不到的示例包；`robot_app` 会生成控制台启动器 `robot_control_suite控制台` |
| `cam` | 弹出本地窗口显示各相机实时画面；按画面分配头部 / 左腕 / 右腕，可交换左右腕、设置 0/90/180/270° 旋转；逐项确认后才保存 |
| `ee` | 弹出本地窗口选择手型（L6 / XHand1）、接线（usb / 485）和左右设备；点"开合测试"核对实物并确认后保存 |
| `xr` | 选择网卡（默认有线），临时启动 PC Service + xr_bridge，收到头显追踪数据后确认绑定，写入 `xr.device_id` |
| `check` | 最终配置检查，不启动模块 |

- 相机和手的确认结果保存在配置的 `setup.cameras` / `setup.ee` 里，并绑定设备映射；改了序列号、旋转、接线或串口后需要重新确认。
- 手只在点"开合测试"并确认后才动作：四指慢速运动到约一半行程再回原姿态，拇指不动。
- **xr_bridge 编译时需要 PC Service 的 SDK**（`/opt/apps/roboticsservice/SDK`，或设 `XRT_SDK_DIR`）。没装时 `xr_teleop` 仍能编译，但不生成 `xr_bridge_node`。
- 头显端：安装 XRoboToolkit App，与电脑处于可互通的局域网；配对时在 App 的 Tracking 里至少勾 Head 或 Controller，并开启 Data & Control 区域的 **Send**。
- 容器用 `--network host` 时 PC Service 直接用物理机网络；保持独立的 `ROS_DOMAIN_ID`，并确认 PC Service 的端口没被占用。

## 3. 日常启动：`./scripts/start.sh`

```bash
./scripts/start.sh                         # 前台启动全部模块，Ctrl+C 停止（运控先切 HOLD）
./scripts/start.sh up [模块...]            # 后台启动，自动先启动依赖
./scripts/start.sh down [模块...]          # 停止；停一个模块会先停依赖它的模块
./scripts/start.sh restart camera_head
./scripts/start.sh status --hz             # 状态、PID、运行时长、话题频率、最近一条错误
./scripts/start.sh logs xr -f              # 日志：logs/<模块>/latest.log
./scripts/start.sh check [config]          # 只校验配置并打印将要启动的内容
./scripts/start.sh -c config/other.yaml status   # 用其他配置文件
```

- **停止运控时**：FSM 不在 HOLD（例如 OCS2）会先询问，确认后先切 HOLD 再停；5 s 内没回到 HOLD 会再次询问。`--yes` 跳过询问（仍然先切 HOLD）。
- 模块状态保存在 `run/`，`start.sh` 退出或控制台重启都不影响已启动的模块。
- 其他：`./scripts/start.sh nav [--map ID] [--map-only]` 导航（`nav --list` 列出地图）；`./scripts/start.sh dyn-identify` 负载辨识向导（交互式，只显示结果不写配置）。

## 4. 网页控制台

### 4.1 启动

| 方式 | 做法 |
|---|---|
| 双击（日常） | 双击**仓库根目录的 `robot_control_suite控制台`**：控制台没运行就在后台启动（日志在 `logs/console/`），然后用默认浏览器打开；已在运行就直接打开 |
| 命令行 | `./scripts/start.sh console --open` |
| 后台管理 | `./scripts/start.sh console start\|stop\|restart\|status`（默认端口 8765，`--port` 指定） |
| 其他电脑访问 | 机器人上 `./scripts/start.sh console --open --host 0.0.0.0`，然后在其他电脑打开 `http://机器人IP:8765/`；或用 SSH 端口转发 `ssh -L 8765:127.0.0.1:8765 <机器人>` 后打开 `http://127.0.0.1:8765/` |

- `robot_control_suite控制台` 是编译 `robot_app` 时生成的本机架构可执行文件，不进 Git；它按自身位置调用 `start.sh console --open`，可以随整个仓库移动，不能单独移出仓库。
- 关闭控制台不会停止已启动的模块。

### 4.2 功能

- **模块**：启动 / 停止 / 重启 / 看日志，状态每秒刷新；"全部启动 / 全部停止"（全部启动包含运控、XR 和相机，不含 RViz 和手柄）。
- **控制模式**：HOLD / HOME / OCS2 / MOVEJ / 切换姿态（HOME ↔ REST），规则与 RViz 的 FSM 面板相同；HOME 和切换姿态先弹窗确认。
- **停止运控**：FSM 不在 HOLD 时弹窗确认，先切 HOLD 再停；切不到 HOLD 会拒绝停止。
- **RViz**：在控制模式区域打开 / 关闭；它只订阅话题，打开或关闭都不影响遥操作。
- **手柄遥操**：选手柄（自动 / jsN）后启动；需要运控已在运行。
- **相机**：扫描设备 → 为头部 / 左腕 / 右腕选序列号和旋转 → 保存到配置（保留注释）；运行中的相机直接预览（每路 ≤10 Hz）。
- **诊断包**：一键导出（同 `./scripts/start.sh diag`，见第 10 节）。

### 4.3 安全

没有登录，明文 HTTP，而且能切换 HOME / OCS2 / MOVEJ 让机械臂运动。默认只监听本机（`127.0.0.1`），这是唯一的访问限制。用 `--host 0.0.0.0` 启动后，同一网络里能访问端口的人都能操作机器人：只在机器人内网使用，需要时用防火墙限制来源（放行 8765 端口）。

## 5. 配置：`config/robot.local.yaml`

配置文件 `config/robot.local.yaml` 由 `./scripts/setup.sh config` 按入口（`--entry whole_body|split_body|dual_arm`）从模板生成，模板在 `src/robot_setup/robot_config/robot_config/templates/`（`base.yaml` 加每个入口一份补丁）。**所有键都必须写**，程序不会补默认值；值写 `null` 表示没设置，由机器人描述包自己的默认值决定。模板改了键之后，每台机器运行一次 `./scripts/setup.sh config`，它把缺的键补上（保留你的值和注释，原文件备份为 `.bak`）。`robot` 里每个部件先写**是什么**（`type`），再写**怎么连**（`interface`）；`control` 是控制参数；`xr` / `cameras` / `joystick` / `navigation` 是遥操作与采集。启动前会校验：缺键、多键（包括旧布局的 `platform` / `hardware` / `defaults`）、类型错误、xhand1 + 485、相机序列号为空等直接报错并指出字段。

| 字段 | 默认 | 说明 |
|---|---|---|
| `robot.entry` | `whole_body` | `whole_body` 全身（WBC）/ `split_body` 分体 / `dual_arm` 双臂 |
| `robot.hardware` | `real` | 运行方式：`real` / `mock_components` / `isaac`；下面各部件的 `interface` 只在真机生效 |
| `robot.base.type` / `robot.base.joints_movable` | 无 / 无 | 底盘：`linkhou_s2` / `linkhou_s2_v2`；关节是否可动 |
| `robot.body.type` / `robot.body.interface.can` | `juxie` / 无 | 腰、头电机（CAN FD）和它的 CAN 接口（默认 `can0`）；改接口后重新 `./scripts/setup.sh host` |
| `robot.arm.type` | `marvin` | 臂驱动，目前只有 `marvin`（天机）有机器模型；`entry` 没有对应模型的臂会报错 |
| `robot.arm.interface.ip` / `robot.arm.interface.firmware` | `192.168.1.190` / 无（初始化时询问） | 臂控制器的以太网地址（接在臂末端 485 口的手也走它）；天机臂 SDK 版本 `338` / `343`，编译时使用，改了要重新 `./scripts/setup.sh build` |
| `robot.end_effector.type` | `linkerhand_l6` | 末端（手或夹爪）：`none` / `linkerhand_l6` / `xhand1` / `wuji_hand2` / `jodell_rg75` |
| `robot.end_effector.interface.bus` | `usb_rs485` | 末端接在哪条线上：`usb_rs485`（485 转 USB 接电脑）/ `arm_rs485`（接机械臂末端 485 口）/ `usb_can`（只给 `linkerhand_l6`）/ `ethernet`（只给 `wuji_hand2`）；`xhand1` 只能 `usb_rs485`，`jodell_rg75` 只能 `arm_rs485` |
| `robot.end_effector.interface.left` / `.right` | 无 | 左右手所选总线用到的项：`port`（`usb_rs485`，`/dev/serial/by-id/…`，`./scripts/setup.sh ee` 确认后写入）、`can`（`usb_can`，默认 `can1` / `can2`）、`channel`（`arm_rs485`，1 / 2 / 3） |
| `robot.end_effector.dyn_param.left` / `.right` | `[]` | 每侧工具负载（10 个数），`[]` = 按末端类型取内置值；`./scripts/setup.sh dyn` 辨识后写入，真机启动时传给驱动 |
| `control.arm_mode` / `control.limits.*` / `control.patch` | `position` / 无 / 无 | 臂控制模式（`position` / `joint_impedance`）；关节最大速度和加速度；对 ros2_control 控制器参数的覆盖 |
| `xr.enable` / `xr.start_pc_service` | `true` / `true` | 启动 xr_bridge / 自动启动 PC Service |
| `xr.frame_timeout_ms` | `300` | 多久没有新帧判为断线（断线时机械臂保持最后目标，PC Service 断开 3 s 后自动重连） |
| `xr.network_mode` | `ethernet` | `ethernet` / `wifi`：电脑接入局域网的网卡 |
| `xr.network_interface` / `xr.device_id` | `""` | 配对时保存的网卡和头显 ID；日常只接收该头显的数据 |
| `cameras.*` | 30 Hz，三台都开 | 按序列号绑定；`rotation` 取 0/90/180/270；`usb_port` 可选 |
| `joystick.device` | `""` | 空 = 自动，或 `/dev/input/jsN` |
| `log.mode` | `normal` | `normal` / `debug`，见第 10.3 节 |

## 6. 遥操作

### 6.1 XR 头显按键

正面键是命令，每个功能一个键、按下即生效、没有组合键；背面键是操作。

| 位置 | 按键 | 功能 |
|---|---|---|
| 正面 | 右 A | 状态机前进：HOME → HOLD → OCS2。进入 OCS2 后手臂待命，还不跟随 |
| 正面 | 左 X | 状态机后退：OCS2 / MOVEJ → HOLD；**HOLD 下再按 → HOME（手臂会动）**；HOME 下切换 HOME ↔ REST |
| 正面 | 右摇杆按下 | 跟随 ↔ 停止（UPDATE ↔ STORAGE）：按下时记录手柄和手臂当前位置，之后双臂跟随手柄；再按停止。只在 OCS2 有效，离开 OCS2 自动停止 |
| 背面 | 左 / 右扳机 | 对应的手或夹爪按比例开合：松开张开，按到底闭合 |

典型流程：右 A 进 OCS2 → 右摇杆按下开始跟随 → 操作 → 右摇杆按下停止 → **左 X 按一次**回 HOLD（在 HOLD 里再按会进 HOME）。其他键目前没有功能。

### 6.2 XR 坐标对齐

控制只用增量：进入跟随时记录手柄与机械臂的基准位姿，之后把手柄位移映射到机械臂上。头显开机时"建立房间"的原点不影响增量，影响的是方向：

- `xr_align_head_yaw: false`（默认）：位移按"进入跟随时手柄的姿态"解释，手柄握得倾斜时，往前推手臂会斜着走。
- `xr_align_head_yaw: true`：进入跟随时读取头显水平朝向，**操作员面朝的方向 = 机器人 +X**，与房间原点和手柄倾角无关。

开关和位移比例 `xr_pose_scale`（建议 0.75~1.5）在机型的 `target_generator.yaml`（`src/robot_description/fa_w2_description/config/ocs2/`）。**真机首次开启对齐前先在 mock / Isaac 验证方向，并调低 `xr_pose_scale`。**

### 6.3 手柄

先确认手柄被识别：`ros2 run joy joy_enumerate_devices`，然后 `./scripts/start.sh up joystick`（或在控制台"手柄遥操"卡片启动）。

| 按键 | 作用 |
|---|---|
| 右摇杆按下 | 启用 / 停用手柄 |
| LB+B | 回 HOLD |
| LB+Y | HOLD → MOVEJ |
| LB+START | HOLD → OCS2 |
| A | 切换左 / 右臂 |
| RB | 切换手臂 / 底盘模式 |
| 左摇杆按下 | 高速 / 低速 |
| Back | 镜像开关 |

不要按 LB+A（HOME）。

### 6.4 无头显联调（xr_stub）

`XrInputHandler` 只有在 `/xr_target_node` 节点存在时才启用 XR，`xr_stub.py` 用同名节点发布头显话题：

```bash
./scripts/start.sh config/mock.yaml            # 前台启动仿真运控（mock_components，关闭 xr 和 cameras）
ros2 run xr_teleop xr_stub.py --script steps.json
```

时间线示例（秒，从 stub 启动算起；未写的字段保持不变）：

```json
[{"at": 9.0, "head_yaw_deg": 90},
 {"at": 10.0, "event": 1},
 {"at": 12.0, "event": 3},
 {"at": 13.0, "left_delta": [0.0, 0.1, 0.0]},
 {"at": 15.0, "event": 3}]
```

`event` 只在该步骤那一帧发送一次：1 = 右 A，2 = 左 X，3 = 右摇杆按下。示例：HOLD 下右 A 进 OCS2，右摇杆开始跟随，左手柄移动 0.1 m，右摇杆停止。

## 7. 相机

| 位置 | 型号 | 驱动 launch | 话题 |
|---|---|---|---|

## 8. 录制与回放

```bash
./scripts/start.sh record [名称]                       # 只录关节：/joint_states、/fsm_state，保存到 bags/
./scripts/start.sh record 名称 --topics collect        # 数采：关节 + 已启用的相机压缩图像
./scripts/start.sh record 名称 --topics xr             # XR：头显话题、目标与当前位姿、/fsm_state
./scripts/start.sh record 名称 --topics /a,/b          # 自定义话题
./scripts/start.sh bags                                # 列出录包
./scripts/start.sh bags --delete 名称 --yes            # 删除
./scripts/start.sh play 名称 [--rate 0.5] [--loop] [--paused] [--start 30]
./scripts/start.sh play 名称 --xr                      # 把头显话题回放给运控（同时运行 xr_stub --silent）
```

- 录包目录默认 `<工作区>/bags`（`record.dir` 可改）；`record.extra_topics` 给每次录制追加话题。
- 磁盘剩余不足 2 GB 时拒绝开始录制。
- 运控运行时不要回放关节录包（`/joint_states`、`/fsm_state` 会和控制器自己发布的冲突）。

## 9. 故障排查

| 现象 | 处理 |
|---|---|
| 不知道哪个部分出问题 | `./scripts/start.sh status --hz` 看哪个模块停止 / 频率为 0 / 有最近错误，再 `./scripts/start.sh logs <模块>` |
| `xr_bridge_node is not built` | 未找到 PC Service SDK：`./scripts/setup.sh host`，然后 `./scripts/setup.sh build` |
| `RoboticsService did not start` | 桌面版 PC Service 需要 `DISPLAY`；无桌面用 headless 版（`XRT_PCS_HEADLESS=1 ./scripts/setup.sh host`） |
| `/teleop/connection_status` 一直为 false | App 未连上 PC Service（同一网段、IP 正确）；看 `logs/xr/latest.log` 里的 `SDK 事件:` 行 |
| 有头显数据但手臂不动 | 状态机需在 OCS2（右 A），再按右摇杆进入跟随；控制日志里有"当前 FSM 不是 OCS2"说明按右摇杆时还没进 OCS2 |
| 相机 `Usb pal is not exist` / 打不开 | udev 规则未装或未重新插拔；序列号是否正确 |
| 腰部 CAN 初始化失败 | 未配置免密 sudo：`./scripts/setup.sh host` |

## 10. 出问题时收集日志

### 10.1 导出诊断包

各模块最近一两分钟收发的数据记在共享内存里，**重启或断电会丢**。出了问题先别重启，在这台机器上执行：

```bash
./scripts/start.sh diag [--minutes N] [原因]        # N 默认 10；控制台的"导出诊断包"是同一件事
```

不用停机器人。结果是 `logs/diag/diag_<时间>.tar.gz` 和同内容的 `.report.txt`，报告按这个顺序看：

| 段 | 看什么 |
|---|---|
| fault codes | 这段时间出现的故障码，停机类（S1/S2）在前；查 [`故障码.md`](故障码.md) 的"先查什么" |
| health | 各组件的 `[HEALTH]` 汇总：控制周期的 `late`、`period max`；XR 和 target_generator 的 `rate`、`longest gap` |
| flight recorder rings | 各模块实际收发了什么；`anomalies, earliest first` 的**第一条是最先出问题的一环** |
| 日志 | 包里 `logs/<单元>.log` 是窗口内的原文 |

异常类型：`stopped`（某模块的记录比别的早停 1 秒以上：崩溃、卡死或被杀）、`gap`（数据流断了超过周期的 4 倍）、`late`（控制周期或硬件读周期超过 1.5 倍）、`jump`（关节命令一个周期跳了 0.2 rad 以上）。

| 现象 | 先看 |
|---|---|
| 机器人不动 | `xr_frame_in` 有没有数据（没有：看 `XR-` 码和 `logs/pc_service/latest.log`）；`tel_target_out` 有没有；FSM 是不是在 HOLD |
| 卡顿 / 抖 | 控制器 `late`、`period max`；`hw_read` 有没有 `late`；`xr_frame_in` 有没有 `gap` |
| 突然停 / 切 HOLD | 停机类故障码；`ctl_fsm` 的切换记录 |
| 某关节怪 | `jump` 指出的关节；对照 `ctl_command` 和 `hw_write` |

诊断包指出哪一环最先出问题，不说为什么；原因要看那一环的日志和代码。

### 10.2 日志在哪

每个模块一份：`logs/<模块>/<时间>.log`，`latest.log` 指向最新一次，每模块保留最新 20 份。`./scripts/start.sh logs <模块> -f` 跟踪；`./scripts/start.sh status` 在系统时钟没同步时会警告（各模块靠系统时钟对齐记录）。

### 10.3 日志模式

`log.mode: normal`（默认）| `debug`，写在 `config/robot.local.yaml`，**一次运行里固定，改了要重启**。debug 把我们自己的组件降到 DEBUG、健康行从每 10 秒缩到每秒一行，不改控制行为，只在排查时短时间用。写日志的规则和记录点见 [`src/robot_utils/README.md`](../src/robot_utils/README.md)。

## 11. 真机逐步验证

重启机器或改动之后按顺序做。每一步给出操作和过关标准，不过关就停在这一步。下面的设备值（网卡、串口序列号、IP）是当前 fa_w2 的配置，换机器时以 `config/robot.local.yaml` 为准。除 11.1 外，命令都在容器 shell 里执行。

### 11.1 宿主机检查

| # | 命令 | 过关标准 |
|---|---|---|
| 1 | `systemctl is-active docker` | `active` |
| 2 | `ip -br link show can0` | 有 `can0` |
| 3 | `ping -c 2 192.168.1.190` | 0% 丢包（机械臂控制器） |
| 4 | `ls /dev/serial/by-id/` | 两行，含 `A9BJTL0I`（左手）和 `AF7IE1RC`（右手） |
| 5 | `lsusb \| grep -ci 2bc5` | `3`（三台相机） |
| 6 | `echo $DISPLAY` | 有值 |
| 7 | 机械臂控制器、腰和头电机、手上电 | 已上电 |

### 11.2 进入容器

```bash
cd <仓库目录>
./docker/run.sh
```

每开一个新终端，重新执行 `./docker/run.sh`。

```bash
test -f /.dockerenv && echo "在容器里" || echo "在宿主机上"
xeyes
sudo -n true && echo sudo-ok
ls /opt/apps/roboticsservice/runService.sh
grep MARVIN_FIRMWARE: build/marvin_hardware/CMakeCache.txt
```

过关标准：`在容器里`；`xeyes` 弹出窗口（Ctrl+C 关闭）；`sudo-ok`；`runService.sh` 存在；固件是 `MARVIN_FIRMWARE:STRING=338`（和配置里的 `robot.arm.interface.firmware: 338` 一致；不一致时 `./scripts/setup.sh check` 会警告，重新 `./scripts/setup.sh build`）。

### 11.3 初始化检查

```bash
./scripts/start.sh check
```

过关标准：显示运控启动命令（`whole_body.launch.py`、`end_effector:=linkerhand_l6`）和三台相机序列号。

依次做相机、手、头显配对（见第 2 节）：

1. `./scripts/setup.sh cam`：遮住左腕镜头，对应画面变黑；再遮右腕。位置不对就点"交换左右腕"；调好旋转后点"应用配置并预览"；三张卡片都勾核对项后"确认并保存"。过关：终端出现 `>>> 相机画面与位置已确认`。
2. `./scripts/setup.sh ee`（手周围无遮挡）：左右手分别点"开合测试"，确认动的是对应的手，勾核对项后"确认并保存"。过关：`>>> 左右手配置已确认`。手不应答时断电 10 秒再上电重试。
3. `./scripts/setup.sh xr`：选网线和对应网卡；头显 App 选终端打印的 PC Service 地址，勾 Head 或 Controller 并开启 Send；收到追踪数据后输入 `y` 绑定。过关：配置里 `xr.device_id` 有值。
4. `./scripts/setup.sh check`。过关：三台相机带旋转；两只手的串口是 `/dev/serial/by-id/…`；相机和手都是"已确认"。

### 11.4 相机

```bash
./scripts/start.sh up camera_head camera_left_wrist camera_right_wrist
./scripts/start.sh status --hz
```

过关标准：三个模块"运行"；约 60 秒后三台 `compressed` 都是 30 Hz。

### 11.5 运控（手臂不动）

急停在手边，手臂周围无人。先探测手：

```bash
python3 -m end_effector_setup.discovery <<< '{"side":"left","operation":"probe","hand":"linkerhand_l6","drive":"usb","port":"/dev/serial/by-id/usb-FTDI_FT232R_USB_UART_A9BJTL0I-if00-port0"}' | grep END_EFFECTOR_RESULT
python3 -m end_effector_setup.discovery <<< '{"side":"right","operation":"probe","hand":"linkerhand_l6","drive":"usb","port":"/dev/serial/by-id/usb-FTDI_FT232R_USB_UART_AF7IE1RC-if00-port0"}' | grep END_EFFECTOR_RESULT
```

过关标准：两行都是 `"ok": true`。不是则给那只手断电 10 秒再上电。

```bash
./scripts/start.sh up control
./scripts/start.sh status --hz
ros2 service call /controller_manager/list_controllers controller_manager_msgs/srv/ListControllers 2>&1 | grep -oE "name='[a-z_]+'|state='[a-z]+'" | paste - -
ros2 topic echo /fsm_state --once 2>/dev/null | grep ^data
grep -n "HW-00\|\[ERROR\]" logs/control/latest.log | grep -v "zenoh\|pal_statistics"
./scripts/nudge.py show
```

过关标准：
- 输出 `>>> 运控就绪：控制器全部激活`，听到臂上电声，`status` 里运控 `FSM=HOLD`；
- 4 个控制器全部 `active`：`whole_body_controller`、`left_hand_controller`、`right_hand_controller`、`joint_state_broadcaster`；
- `fsm_state` 是 `data: 2`；
- 日志里没有 `HW-00x`；`[ERROR]` 只允许启动时左右手各一条 `Failed to read L6 hand position`；
- `nudge.py show` 的头和腰 6 个关节有数值，手臂没有动作。

### 11.6 灵巧手

```bash
./scripts/nudge.py fsm movej
grep -c "Failed to read L6 hand position\|Failed to write" logs/control/latest.log
ros2 topic pub --once /left_hand_controller/target_percent std_msgs/msg/Float64 "{data: 0.5}"
ros2 topic pub --once /left_hand_controller/target_command std_msgs/msg/Int32 "{data: 1}"
ros2 topic pub --once /left_hand_controller/target_command std_msgs/msg/Int32 "{data: 0}"
```

每条等 3 秒观察。右手把 `left_hand_controller` 换成 `right_hand_controller` 重复，最后再数一次超时计数。

过关标准：`fsm_state: 4` 且没有运动；手指按命令开合，`0.5` 在张开和闭合之间；超时计数没有增长。

### 11.7 头和腰

状态机在 MOVEJ。每条等它打印"到位"再做下一条：

```bash
./scripts/nudge.py head 1 0.05
./scripts/nudge.py head 1 -0.05
./scripts/nudge.py head 2 0.05
./scripts/nudge.py head 2 -0.05
./scripts/nudge.py waist 0.05
./scripts/nudge.py waist -0.05
./scripts/nudge.py fsm hold
```

过关标准：每条都打印 `到位`（静差不超过 0.003 rad），回位后回到原值；最后 `fsm_state: 2`。不要试腰的升降、位姿、`body_joint1~3`，不要让头大幅运动。

### 11.8 停止运控

```bash
./scripts/start.sh down control
ps -eo pid,args | grep -E "ros2_control_node|whole_body.launch|rviz2" | grep -v grep
```

过关标准：`down` 完成；日志最后是 `process has finished cleanly`、`Robot released`；`ps` 没有输出。再次启动运控前，重新做 11.5 开头的手探测。

### 11.9 遥操作

手臂在这里第一次跟随，不过关立即回 HOLD（手柄 LB+B，头显左 X）或急停。

**手柄**：`./scripts/start.sh up control` 和 `./scripts/start.sh up joystick`；右摇杆启用，LB+START 进 OCS2，小幅推摇杆。过关：手臂按摇杆方向小幅跟随；LB+B 后回 HOLD，手臂停住。

**头显**：

```bash
./scripts/start.sh up control
./scripts/start.sh up xr
ros2 topic echo /teleop/connection_status --once 2>/dev/null | grep ^data
```

按 6.1 节的流程：右 A 进 OCS2，右摇杆按下开始跟随，小幅移动；右摇杆按下停止，左 X 按一次回 HOLD。

过关标准：`up xr` 输出 `>>> 头显已连接，正在接收追踪数据`（没连上时输出 `[警告]` 和缺什么）；`data: true`；跟随时整条手臂不上下晃，方向和幅度合理；左 X 一次后 `fsm_state` 是 `data: 2`。

### 11.10 收尾

```bash
./scripts/start.sh down
ps -eo pid,args | grep -E "ros2_control_node|whole_body.launch|rviz2" | grep -v grep
exit
```

过关标准：`down` 完成，`ps` 没有输出。
